# 谷芯快检云检测仪数据上传接口对接说明

版本：v0.1  
适用对象：检测仪厂家业务人员、技术人员  
联系电话：13363412262

## 一、对接目标

检测仪完成检测后，将检测结果自动上传至谷芯快检云。谷芯快检云根据设备编号把检测记录归属到对应客户企业，用于客户查看检测记录、开具合格证、扫码查询和后续留档。

本次对接不要求厂家理解谷芯后台内部结构。厂家只需要按约定格式上传检测数据，并按签名规则保证请求来源可信。

## 二、整体流程

1. 谷芯在后台创建厂家接口，分配 `manufacturer_code`；
2. 谷芯生成或录入厂家对接密钥 `access_secret`；
3. 谷芯把检测仪设备编号 `device_sn` 绑定到客户企业；
4. 厂家在设备或厂家系统中配置上传地址、厂家编码、设备编号和密钥；
5. 检测仪完成检测后上传 JSON 数据；
6. 谷芯快检云校验签名和设备绑定关系；
7. 系统生成检测记录和检测项目明细；
8. 合格记录进入可开证列表，不合格记录仅用于查看和留档。

## 三、接口地址

| 环境 | 地址 |
| --- | --- |
| 正式测试环境 | `https://api.gxkjy.com/api/open/detection/upload` |
| 正式生产环境 | 由谷芯上线前另行确认 |

请求方式：`POST`  
请求格式：`Content-Type: application/json`  
认证方式：HMAC-SHA256 签名

## 四、数据归属规则

系统只根据以下两个字段判断检测数据属于哪家客户：

```text
manufacturer_code + device_sn
```

说明：

1. `manufacturer_code` 由谷芯分配给厂家；
2. `device_sn` 是检测仪唯一设备编号；
3. 谷芯后台会提前把设备编号绑定到客户企业；
4. 厂家不需要上传企业名称；
5. 即使上传企业名称，系统也不会依赖该字段判断归属。

这样做可以避免客户手填错误、企业名称不一致、设备串用等问题。

## 五、请求字段

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| manufacturer_code | string | 是 | 厂家编码，由谷芯分配 |
| device_sn | string | 是 | 检测仪设备编号，必须与后台绑定一致 |
| manufacturer_record_id | string | 是 | 厂家侧本条检测记录唯一 ID，用于防重复 |
| timestamp | number | 是 | Unix 秒级时间戳 |
| nonce | string | 是 | 随机字符串，用于防止重放 |
| sign | string | 是 | HMAC-SHA256 签名 |
| sample_name | string | 是 | 样品名称，如西红柿、黄瓜、猪肉 |
| product_name | string | 否 | 产品名称，可与样品名称相同 |
| test_time | string | 是 | 检测时间，建议格式 `YYYY-MM-DD HH:mm:ss` |
| result | string | 是 | 整条记录结论：qualified/unqualified/unknown |
| items | array | 是 | 检测项目数组，至少 1 条 |

## 六、检测项目字段

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| item_name | string | 是 | 检测项目名称 |
| method | string | 否 | 检测方法 |
| value | string | 是 | 检测结果值 |
| unit | string | 否 | 单位 |
| limit_value | string | 否 | 限量值或判定阈值 |
| result | string | 是 | 单项结论：qualified/unqualified/unknown |
| conclusion | string | 否 | 中文结论，如合格、不合格 |
| raw_value | string | 否 | 原始检测值 |
| reagent_batch | string | 否 | 试剂批号 |
| remark | string | 否 | 备注 |

## 七、签名规则

厂家拥有 `access_secret`。该密钥只保存在厂家系统和谷芯后台，请不要放在请求参数中，也不要发到公开群或文档中。

第一版签名只对核心字段签名：

1. manufacturer_code；
2. device_sn；
3. manufacturer_record_id；
4. nonce；
5. timestamp。

待签名字符串按以下顺序拼接：

```text
manufacturer_code=GXTEST&device_sn=GXDEMO001&manufacturer_record_id=REC202607120001&nonce=abc123xyz&timestamp=1783833600
```

签名算法：

```text
HMAC-SHA256
```

签名输出：

```text
hex 小写字符串
```

说明：

1. `sign` 字段不参与签名；
2. `items` 数组第一版不参与签名，避免 JSON 序列化差异；
3. 空值字段不建议参与签名；
4. 时间戳超过 5 分钟会被拒绝；
5. 同一个 `nonce` 重复使用会被拒绝；
6. 同一个 `manufacturer_record_id` 重复上传不会重复生成检测记录。

## 九、返回结果

### 成功

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "record_id": "系统检测记录ID",
    "status": "accepted"
  }
}
```

### 重复上传

```json
{
  "code": 0,
  "message": "duplicate accepted",
  "data": {
    "status": "duplicate"
  }
}
```

### 失败

失败时会返回清楚原因，但不会返回数据库错误、服务器异常堆栈或密钥。

常见失败原因：

| 场景 | 说明 |
| --- | --- |
| 签名错误 | sign 不正确或签名字段不一致 |
| 厂家编码不存在 | manufacturer_code 未在谷芯后台配置 |
| 设备编号未绑定 | device_sn 未绑定客户企业 |
| 时间戳过期 | timestamp 超出允许时间范围 |
| nonce 重复 | 同一随机字符串已使用 |
| 字段缺失 | 必填字段为空 |
| 检测项目为空 | items 为空数组 |
| 数据格式错误 | JSON 格式或字段类型不符合要求 |

11. 双方确认异常错误提示和上传日志。

## 十一、常见问题

### 1. 为什么不按企业名称归属数据？

企业名称容易出现简称、错字、空格、旧名称等问题。使用设备编号绑定企业更稳定。

### 2. 不合格数据会不会丢？

不会。不合格数据会进入检测记录，用于查看和留档，但不能开具合格证。

### 3. 上传失败怎么办？

厂家设备或系统应保留失败日志，并支持重试。谷芯也会保留上传日志用于排查。

### 4. 密钥能不能放在请求里？

不能。请求只传签名 `sign`，不传 `access_secret`。

### 5. items 为什么不参与签名？

第一版为了降低接入难度，避免不同系统 JSON 排序和空值处理不一致。后续如需要更高安全级别，可以升级为 `body_hash`。
