# 谷芯快检云检测数据对接文档

适用于检测仪器厂家向谷芯快检云上传食品安全快检数据

版本：V1.0  
适用对象：检测仪器厂家技术人员  
文档日期：2026-07-10

## 1. 文档说明

本文档用于说明检测仪器厂家如何向谷芯快检云上传食品安全快检数据。厂家按照本文档完成接口开发后，检测仪器产生的快检数据可进入谷芯快检云，用于企业日常自检留档、检测记录查看和合格证开具辅助。

本文档只说明对外数据上传协议，不包含谷芯快检云内部实现、数据库结构、后台账号、客户小程序页面或打印设备相关内容。

## 2. 对接目标

本次对接目标如下：

1. 检测仪器可通过 HTTPS 主动上传快检数据。
2. 上传数据包含设备信息、检测记录、检测项目明细和检测结论。
3. 谷芯快检云可根据厂家编码和设备编号识别数据来源。
4. 谷芯快检云可根据检测结论判断该记录是否可用于后续开具合格证。
5. 系统支持签名校验、防重复上传和异常上传记录。

## 3. 对接流程总览

1. 谷芯科技创建厂家接口配置。
2. 谷芯科技登记测试设备。
3. 谷芯科技将测试设备绑定到测试企业。
4. 谷芯科技向厂家提供测试环境地址、厂家编码、设备编号和签名密钥。
5. 厂家按本文档组装 JSON 请求数据。
6. 厂家按签名规则生成 `sign`。
7. 厂家调用检测数据上传接口。
8. 谷芯科技在平台中查看上传日志和检测记录。
9. 双方核对字段、单位、枚举值、检测结论和异常处理方式。
10. 确认无误后切换到正式环境。

## 4. 接口基本信息

正式环境：

```http
POST https://api.xxx.com/api/open/detection/upload
```

测试环境：

```http
POST https://api-test.xxx.com/api/open/detection/upload
```

说明：

1. 实际域名由谷芯科技在部署或联调时提供。
2. 所有接口必须使用 HTTPS。
3. 请求格式为 JSON。
4. `Content-Type` 使用 `application/json`。
5. 字符编码使用 UTF-8。

## 5. 请求方式

| 项目 | 要求 |
|---|---|
| HTTP Method | POST |
| Content-Type | application/json |
| 字符编码 | UTF-8 |
| 请求体格式 | JSON |
| 传输协议 | HTTPS |
| 超时时间建议 | 10 秒 |
| 重试建议 | 网络失败可重试，同一检测记录必须保持同一个 `manufacturer_record_id` |

## 6. 鉴权与签名规则

### 6.1 必填鉴权字段

每次请求中必须包含以下字段：

| 字段 | 说明 |
|---|---|
| `manufacturer_code` | 厂家编码，由谷芯科技分配 |
| `device_sn` | 设备编号，由双方确认 |
| `manufacturer_record_id` | 厂家侧检测记录唯一编号 |
| `timestamp` | 请求时间戳 |
| `nonce` | 随机字符串 |
| `sign` | 签名值 |

### 6.2 签名规则

1. 谷芯科技为每个厂家分配 `manufacturer_code` 和 `access_secret`。
2. `access_secret` 只用于签名，不应出现在请求明文字段中。
3. `timestamp` 与服务器时间差不得超过 5 分钟。
4. 同一个 `manufacturer_code + nonce` 在 5 分钟内只能使用一次。
5. 重复上传判断依据为 `manufacturer_code + device_sn + manufacturer_record_id`。
6. 签名算法为 HMAC-SHA256。
7. `sign` 建议使用小写十六进制字符串。

### 6.3 待签名字符串

待签名字符串按以下顺序拼接：

```text
HTTP_METHOD + "\n" +
PATH + "\n" +
manufacturer_code + "\n" +
device_sn + "\n" +
manufacturer_record_id + "\n" +
timestamp + "\n" +
nonce + "\n" +
body_hash
```

其中：

| 项目 | 说明 |
|---|---|
| `HTTP_METHOD` | 固定为 `POST` |
| `PATH` | 固定为 `/api/open/detection/upload` |
| `body_hash` | 请求 body 去除 `sign` 字段后的 JSON 字符串 SHA256 摘要 |

如厂家现有设备暂时不支持上述签名方式，请提前说明设备支持的鉴权方式，双方再确认简化方案。第一版标准方案仍以 HMAC-SHA256 为准。

## 7. 请求字段说明

### 7.1 顶层字段

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `manufacturer_code` | string | 是 | 厂家编码 |
| `device_sn` | string | 是 | 设备编号 |
| `manufacturer_record_id` | string | 是 | 厂家侧检测记录唯一编号 |
| `timestamp` | string | 是 | 请求时间戳，ISO 8601 格式 |
| `nonce` | string | 是 | 随机字符串，建议每次请求唯一 |
| `sign` | string | 是 | HMAC-SHA256 签名值 |
| `data` | object | 是 | 检测数据主体 |

### 7.2 data 字段

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `sample_name` | string | 是 | 样品名称 |
| `product_name` | string | 是 | 产品名称 |
| `overall_result` | string | 是 | 总体检测结果，见枚举说明 |
| `test_time` | string | 是 | 检测时间，ISO 8601 格式 |
| `operator_name` | string | 否 | 检测人员 |
| `batch_no` | string | 否 | 批次号 |
| `remark` | string | 否 | 备注 |
| `items` | array | 是 | 检测项目明细数组 |

`overall_result` 枚举：

| 值 | 说明 |
|---|---|
| `qualified` | 合格 |
| `unqualified` | 不合格 |

## 8. 检测项目明细字段说明

`items` 数组中每个检测项目包含以下字段：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `test_item` | string | 是 | 检测项目名称 |
| `test_method` | string | 否 | 检测方法 |
| `test_value` | string | 是 | 检测数值或检测结果文本 |
| `unit` | string | 否 | 单位 |
| `standard_limit` | string | 否 | 标准限值或判定依据 |
| `result` | string | 是 | 单项判定结果 |
| `remark` | string | 否 | 备注 |

`result` 枚举：

| 值 | 说明 |
|---|---|
| `qualified` | 合格 |
| `unqualified` | 不合格 |

## 10. 成功返回示例

```json
{
  "success": true,
  "data": {
    "record_no": "DR20260710000001",
    "manufacturer_record_id": "MFR001-20260710-000001",
    "status": "accepted",
    "message": "检测数据接收成功"
  },
  "message": "ok"
}
```

说明：

1. `accepted` 表示系统已接收该检测数据。
2. 如果检测结果为合格，后续客户可在业务端开具合格证。
3. 如果检测结果为不合格，系统只留档，不允许开具合格证。

## 11. 失败返回示例

失败返回统一格式：

```json
{
  "success": false,
  "message": "错误说明",
  "code": "ERROR_CODE"
}
```

示例：

```json
{
  "success": false,
  "message": "签名错误",
  "code": "INVALID_SIGNATURE"
}
```

## 12. 错误码说明

| 错误码 | 说明 |
|---|---|
| `INVALID_SIGNATURE` | 签名错误 |
| `TIMESTAMP_EXPIRED` | 时间戳超出允许范围 |
| `DUPLICATE_NONCE` | nonce 重复 |
| `DUPLICATE_RECORD` | 检测记录重复上传 |
| `MANUFACTURER_DISABLED` | 厂家接口已停用 |
| `DEVICE_NOT_FOUND` | 设备未登记 |
| `DEVICE_DISABLED` | 设备已停用 |
| `DEVICE_NOT_BOUND` | 设备未绑定企业 |
| `INVALID_RESULT` | 检测结果枚举不合法 |
| `INVALID_PAYLOAD` | 请求字段不完整或格式错误 |
| `SERVER_ERROR` | 服务器内部错误 |

## 13. 数据去重规则

1. `manufacturer_code + device_sn + manufacturer_record_id` 作为唯一检测记录标识。
2. 同一条检测记录重复上传时，系统不会重复入库。
3. 如果厂家需要重新上传修正数据，需要提前与谷芯科技确认处理方式。
4. 第一版不建议厂家通过覆盖方式修改已上传数据。

## 14. 设备归属规则

1. 系统通过 `manufacturer_code + device_sn` 识别设备。
2. 设备必须先由谷芯科技在平台中登记。
3. 设备必须绑定到具体企业。
4. 未登记设备上传数据，不进入正式检测记录。
5. 未绑定企业的设备上传数据，不进入正式检测记录。
6. 停用设备上传数据，不进入正式检测记录。
7. 上述异常上传会被系统记录日志，方便后续排查。

## 15. 检测结果判定规则

1. 第一版系统以厂家上传的 `overall_result` 作为总体判定。
2. `items` 中每个检测项目也需要提供 `result`。
3. 如果任一关键检测项目为 `unqualified`，`overall_result` 应为 `unqualified`。
4. 合格数据可进入可开证流程。
5. 不合格数据只留档，不允许开具合格证。
6. 后续如需要由谷芯快检云根据限值自动判定，双方另行确认规则。

## 16. 时间格式要求

1. `timestamp` 使用 ISO 8601 格式，建议带 `+08:00` 时区。
2. `test_time` 使用 ISO 8601 格式，建议带 `+08:00` 时区。
3. 示例：`2026-07-10T10:30:00+08:00`。
4. 系统业务日期按北京时间处理。

## 17. 联调测试账号和测试设备

联调示例使用以下测试信息：

| 项目 | 值 |
|---|---|
| 测试厂家编码 | `MFR001` |
| 测试设备编号 | `GXTEST001` |

注意：

1. 该测试信息仅用于联调示例。
2. 正式对接时，由谷芯科技分配正式厂家编码、设备编号和签名密钥。
3. `access_secret` 不应通过普通聊天工具明文发送，建议通过安全方式单独交付。

## 18. 联调步骤

1. 谷芯科技创建厂家接口配置。
2. 谷芯科技登记测试设备。
3. 谷芯科技将测试设备绑定到测试企业。
4. 谷芯科技向厂家提供测试环境地址、`manufacturer_code`、`device_sn`、`access_secret`。
5. 厂家按本文档组装 JSON。
6. 厂家按签名规则生成 `sign`。
7. 厂家调用上传接口。
8. 谷芯科技在平台中查看上传日志和检测记录。
9. 客户侧业务端查看检测记录。
10. 合格记录可生成合格证。
11. 双方确认字段、单位、枚举值和检测结果是否正确。
12. 确认无误后切换正式环境。

## 19. 厂家需要确认的问题

请厂家技术人员确认以下问题，并在联调前反馈：

1. 设备是否支持主动 HTTP POST 上传数据？
2. 设备是否支持 HTTPS？
3. 设备是否支持 JSON 格式？
4. 设备是否能配置上传接口地址？
5. 设备是否能保存厂家编码和设备编号？
6. 设备是否能生成唯一检测记录编号？
7. 设备是否能提供检测时间？
8. 设备是否能提供样品名称、产品名称？
9. 设备是否能提供每个检测项目的检测值、单位、限值、判定结果？
10. 设备是否能提供总体判定结果？
11. 设备是否支持 HMAC-SHA256 签名？
12. 如果不支持签名，设备支持什么鉴权方式？
13. 设备是否能在断网后补传数据？
14. 设备重复上传时，是否能保持同一个 `manufacturer_record_id`？
15. 厂家检测结果字段当前有哪些枚举值？
16. 厂家单位字段是否统一？
17. 厂家是否能提供一份真实样例 JSON？
18. 厂家是否能提供接口联调技术联系人？

## 20. 注意事项

1. 本接口用于企业快检数据上传、留档和合格证开具辅助。
2. 平台展示的检测数据来源于企业快检设备。
3. 平台展示内容不等同于第三方检验检测机构出具的检验报告。
4. 厂家应保证上传数据真实、完整、可追溯。
5. 同一条检测记录不要频繁变更 `manufacturer_record_id`。
6. 如字段有差异，请厂家提供真实样例，由谷芯科技确认映射规则。
