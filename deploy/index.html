States

常见状态先分类，再排查

这部分把部署 README 的排障说明转成客户能理解的状态语言。

页面能打开，但看不到业务数据

优先确认数据库是否已初始化、账号是否有数据权限、前端 API 地址是否指向正式接口。

  • 适用场景：后台列表为空、证书记录为空、产品资料为空。
  • 客户判断：界面可访问，但业务内容还没有准备好。

页面长时间转圈，接口没有完成

优先看浏览器请求、后端日志、数据库连接状态，以及 Nginx 是否把接口正确代理到后端。

  • 适用场景：登录等待、列表加载不结束、提交后无反馈。
  • 客户判断：不是页面缺失，而是请求链路需要排查。

出现 404、500、502 或证书错误

先区分前端路由、后端异常、反向代理和 HTTPS 证书四类问题，再进入对应处理。

  • 适用场景：接口错误、页面不存在、HTTPS 警告。
  • 客户判断：需要按入口和错误码定位，不建议反复刷新。

登录、上传或公开文件访问失败

重点检查账号权限、上传目录权限、文件挂载和公开读取路径。

  • 适用场景：上传失败、文件 403、账号无法进入。
  • 客户判断：通常是权限或路径配置问题，不代表业务流程不可用。

备份执行后没有文件或文件异常

优先检查备份任务输出、数据库连接变量、备份目录挂载和磁盘空间。

  • 适用场景：上线验收前备份、运维交接检查。
  • 客户判断：备份需要实际执行验证，不能只看配置存在。

Support

交付后维护重点

后续维护不靠记忆，按入口、备份、日志、风险和变更纪律推进。

待确认事项

官网 `gxkjy.com` 当前说明中保留了是否强制 HTTPS 的决策点。正式上线前建议确认后统一调整路由策略。

上线前

确认域名、证书、环境变量、上传目录和备份位置。

上线当天

按验收清单逐项检查后台、接口、公开页、官网和上传访问。

日常维护

保留日志、执行备份、检查证书有效期和上传目录容量。

功能变更

先确认影响范围，再重建相关服务，避免在运行容器内临时改文件。
